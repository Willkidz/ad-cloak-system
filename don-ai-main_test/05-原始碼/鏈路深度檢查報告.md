# 斗篷系統鏈路深度檢查報告

**檢查時間**：2026-04-03
**檢查範圍**：從前台 UI 到後端 API、Worker、D1 資料庫、N8N 工作流的完整資料鏈路。

經過對線上實際運行的程式碼（Cloudflare Workers、N8N 配置、D1 Schema）的深度檢查，發現了以下嚴重問題與邏輯斷層，按嚴重程度排序如下：

## 🔴 嚴重錯誤 (Critical)

### 1. 多像素 (ad_pixels / bc_pixels) 儲存斷層
- **前台 (`Pixels.tsx`)**：在儲存廣告活動時，正確組裝了 `ad_pixels` 和 `bc_pixels` 的 JSON 陣列並發送給後端 API。
- **後端 API (`cloak-admin-api`)**：在 `POST /api/v1/campaigns` 和 `PUT /api/v1/campaigns/:id` 中，**完全遺漏了** `ad_pixels` 和 `bc_pixels` 欄位。這導致前台設定的多像素資料根本沒有存入 `campaigns` 表。
- **資料庫 (`campaigns` 表)**：雖然 D1 實際表結構中有 `ad_pixels` 和 `bc_pixels` 欄位，但因為 API 沒有寫入，這些欄位永遠是空的。
- **影響**：N8N 無法讀取到多像素資料，導致多像素回傳功能完全失效。

### 2. `clicks` 表缺少 `event_id` 欄位
- **寫入端 (`shadow-cloak`)**：在 `INSERT INTO clicks` 語句中，試圖寫入 `event_id`（語句有 19 個問號，包含 `event_id`）。
- **資料庫 (`clicks` 表)**：經過對線上 D1 執行 `PRAGMA table_info(clicks)`，確認 **`clicks` 表根本沒有 `event_id` 欄位**（共有 49 個欄位，但沒有 `event_id`）。
- **影響**：這會導致 `shadow-cloak` 在插入點擊記錄時拋出 SQL 錯誤（"no such column: event_id"），導致整個點擊追蹤失效，後續的 N8N 歸因也就無從查起。

### 3. BC 追蹤參數斷層 (`money-page` 接收不到參數)
- **傳遞端 (`shadow-cloak`)**：`shadow-cloak` 在後端使用 `fetch` 獲取 `money-page` 時，URL 是 `?t=moneyPageId&vid=visitorId&liff_id=liffId&ac=adCode`，**沒有傳遞 `tag`, `fbclid`, `fbc`, `fbp`**。
- **接收端 (`money-page`)**：`money-page` 內的 BC 追蹤腳本 (`// BC 像素追蹤 - v1.10.3`) 試圖從 `window.location.search` 讀取 `tag`, `fbclid`, `fbc`, `fbp`。
- **影響**：因為 `money-page` 是被 `shadow-cloak` 注入到原始域名的，用戶瀏覽器上的 URL 雖然可能有 `fbclid`，但**沒有 `tag` 參數**。腳本會 fallback 到 `tag='js'`，導致所有 BC 追蹤事件都被錯誤地發送到 `js.freshpathlab.com`，且無法正確歸因。

## 🟠 中度問題 (Warning)

### 4. `line-login-callback` 的 `CREATE TABLE` 缺少 `ad_code`
- **問題**：`line-login-callback` 中的 `POST /bind` 路由會在寫入前執行 `CREATE TABLE IF NOT EXISTS line_user_bindings`，但這個建表語句**缺少了 `ad_code` 欄位**。
- **影響**：雖然目前 D1 中的 `line_user_bindings` 已經透過 `003_add_ad_code.sql` 手動加上了 `ad_code` 欄位，但如果系統在全新環境部署，會因為這個建表語句不完整，導致後面的 `INSERT` 語句報錯。

### 5. `fbc` 參數的產生邏輯缺失
- **問題**：`shadow-cloak` 會從 URL 讀取 `fbclid` 和 `fbc`，並存入 `clicks` 表。但是，如果 URL 只有 `fbclid` 而沒有 `fbc`，`shadow-cloak` **並沒有將 `fbclid` 轉換為 `fbc` 格式**（例如 `fb.1.1234567890.fbclid`）。
- **影響**：Meta CAPI 建議同時提供 `fbp` 和 `fbc`。缺少轉換邏輯會導致許多點擊只有 `fbclid` 而沒有 `fbc`，降低 CAPI 的匹配率。

### 6. CAPI Token 傳遞方式不一致
- **`shadow-cloak`**：發送 PageView 時，將 `access_token` 放在 JSON Body 中。
- **N8N 工作流**：發送 CompleteRegistration 時，將 `access_token` 放在 URL Query Parameter 中 (`?access_token=...`)。
- **影響**：雖然 Meta API 同時支援這兩種方式，但架構上不統一，未來維護容易產生混淆。

## 🟡 邏輯檢查確認 (Passed)

以下環節經過檢查，邏輯正確：
1. **主域名跳轉**：`shadow-cloak` 能正確用 `hostname` 查詢 `campaigns` 表。
2. **斗篷過濾**：`shadow-cloak` 的過濾邏輯（Bot 檢測、OS 檢查、GeoIP 檢查）運作正常。
3. **vid 產生**：正確產生 UUID 作為 `visitorId` 並傳遞。
4. **落地頁 CTA 按鈕**：`money-page` 使用 `HTMLRewriter` 正確替換了 `href` 包含 `freshpathlab` 的 a 標籤，並加上了 `vid` 和 `ac`。
5. **加好友 URL**：`line-login-callback` 中已經有清理 `@` 的邏輯（`const cleanOaId = TARGET_OA_ID.startsWith('@') ? TARGET_OA_ID.substring(1) : TARGET_OA_ID;`），避免了雙重 `@` 問題。
6. **N8N 歸因比對**：N8N 正確使用 `line_user_id` 查詢 `line_user_bindings` 和 `clicks`，進行 Exact Match。

## 🛠️ 建議修復方案

1. **修復 cloak-admin-api**：在 `POST /api/v1/campaigns` 和 `PUT /api/v1/campaigns/:id` 中加入 `ad_pixels` 和 `bc_pixels` 的處理邏輯（需使用 `JSON.stringify` 存入）。
2. **修復 clicks 表結構**：立即在 D1 中執行 `ALTER TABLE clicks ADD COLUMN event_id TEXT;`，否則點擊寫入會失敗。
3. **修復 money-page BC 追蹤**：修改 `shadow-cloak` 的 `injectMoneyPageCode`，將 `tag` 作為全域變數注入到 HTML 中（例如 `<script>window.__TAG__ = '${tag}';</script>`），讓 BC 腳本從全域變數讀取，而不是依賴 URL。
4. **新增 fbc 轉換邏輯**：在 `shadow-cloak` 中加入邏輯，如果存在 `fbclid` 但沒有 `fbc`，自動生成 `fbc` (`fb.1.${Date.now()}.${fbclid}`)。
