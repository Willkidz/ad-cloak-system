### BUG-25｜廣告日誌語言列全部顯示「-」

| 項目 | 說明 |
|:---|:---|
| **所屬模塊** | 廣告日誌 |
| **問題描述** | 「語言」列全部顯示為「-」，數據可能未被收集。 |
| **預期行為** | 應正確顯示訪客的瀏覽器語言（如 `zh-TW`、`en-US`）。 |

**修復方向**

後端為主。檢查寫入 `cloak_logs` 的邏輯（位於 `shadow-cloak` Worker 中），確認是否從請求頭 `Accept-Language` 中提取了語言資訊並寫入 `language` 欄位。若該欄位目前未被寫入，需在日誌記錄邏輯中新增 `const language = request.headers.get('Accept-Language')?.split(',')[0] || '-'`。

### BUG-26｜廣告日誌訪問日誌 Tab IP 顯示 unknown

| 項目 | 說明 |
|:---|:---|
| **所屬模塊** | 廣告日誌 |
| **問題描述** | 部分記錄的訪問 IP 顯示為「unknown」；且訪問日誌 Tab 下「日誌（攔截原因）」列消失。 |
| **預期行為** | IP 應盡可能顯示真實值；表格列應根據 Tab 類型正確顯示。 |

**修復方向**

後端方面，檢查日誌寫入時獲取 IP 的邏輯，Cloudflare Workers 環境中應優先使用 `request.headers.get('CF-Connecting-IP')`，其次 `request.headers.get('X-Forwarded-For')`。前端方面，檢查訪問日誌 Tab 的表格列定義，確認是否遺漏了「日誌（攔截原因）」列的定義，或是否有條件渲染邏輯錯誤地隱藏了該列。

### BUG-27｜域名解析空白提交無驗證提示

| 項目 | 說明 |
|:---|:---|
| **所屬模塊** | 域名短鏈 |
| **問題描述** | 未輸入域名直接提交時，無任何驗證提示或錯誤訊息。 |
| **預期行為** | 應提示「請輸入域名」。 |

**修復方向**

前端問題。在「解析域名」按鈕的處理函數開頭，加入輸入值的非空判斷。若為空，調用 `toast.error('請輸入域名')` 並 `return`。可額外加入域名格式的正則驗證。

## 七、注意事項

1. **不要修改舊表**：`ad_config`、`clicks`、`line_config` 是線上運行中的表，嚴禁修改。
2. **D1 限制**：單次查詢最大 5MB 結果，單筆寫入最大 1MB。
3. **Workers 限制**：單次請求最大 10ms CPU time（免費版），外部 fetch 有次數限制。
4. **前端路由**：使用 React Router，Cloudflare Pages 需要 `_redirects` 檔案支援 SPA 路由。
5. **CORS**：後端已設定允許 `admin.bexnua.store` 跨域，若新增 API 端點需確認 CORS 配置。
6. **每次修改完都要 build + 部署，並回報修復結果與驗證截圖。**
7. **UI 風格**：所有新增或修改的 UI 元素須遵循《通用環境指令》第八節的風格規範（主色 `#7c3aed`、shadcn/ui 元件庫、Tailwind CSS）。
