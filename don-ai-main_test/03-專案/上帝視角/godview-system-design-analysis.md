# 系統設計深度解析：回應 Code 用意、職責劃分與數據必要性

本文旨在回應關於系統設計的核心問題，並根據使用者回饋，重新定義 n8n 與 Google Sheets 的角色，以校準系統的設計方向。我們將正面回應關於 `code` 欄位的用意、系統的職責劃分，以及特定數據欄位的必要性。

---

## 1. 職責劃分：n8n (後台) vs. Google Sheets (前台)

<rule id="backend-frontend-division">
為了確保雙方理解一致，我們採納「後台 vs. 前台」的框架，將系統各組件的職責重新整理如下：
</rule>

| 平台 | 角色定位 | 核心任務 | 結論 |
| :--- | :--- | :--- | :--- |
| **n8n** | **後台 (Backend)** | **配置與生成中心**：生成追蹤用的子域名、設定 LINE Message API 的 Token、綁定 Meta Pixel 與 CAPI Token、處理 LINE API 的 Webhook 事件 | n8n 是一個**無介面的設定與歸因處理中心**，專注於執行自動化任務與處理機器間的溝通。 |
| **Google Sheets** | **前台 (Frontend)** | **營運儀表板**：監控各廣告 (`code`) 的消耗與成效、評估不同素材的表現、提供可直接複製到廣告後台的追蹤鏈結、即時驗證歸因偵測率的準確性 | Sheets 是一個**有介面的人工操作中心**，作為日常監控、決策與操作的主要場域。 |

此職責劃分清晰地界定了兩個平台的用途，後續討論將基於此共識進行。

---

## 2. `code` 欄位的用意：解決「如何分辨」的問題

`code` 欄位本身（如 `01`, `02`）確實無法提供足夠的上下文來分辨其代表的具體廣告。它的核心用意是作為一個**獨一無二的「主鍵 (Primary Key)」**，將「前台 (Sheets)」和「後台 (n8n)」的所有數據串連起來，如同每個廣告活動的身分證字號。

為了讓這個「身分證字號」對營運人員產生意義，我們需要在「前台 (Sheets)」中，為其配上人類可以理解的描述性資訊。這正是 `成效分頁` 中其他欄位的目的。

<example id="code-field-mapping">

| 欄位 (Sheets) | 目的 | 範例 | 如何解決「分辨」問題 |
| :--- | :--- | :--- | :--- |
| **`code`** | **唯一識別碼 (ID)** | `01` | 機器用來關聯所有數據。 |
| **`項目`** | **人工描述** | `獨角仙AI算牌` | **解答1：這是什麼產品的廣告。** |
| **`素材名稱`** | **人工描述** | `美女帥哥圖_文案A` | **解答2：這是哪個素材的廣告。** |
| **`廣告帳戶ID`** | **系統資訊** | `act_123456789` | **解答3：這是從哪個廣告帳號投的。** |
| **`人員`** | **人工描述** | `JS` | **解答4：這是分配給誰的。** |

</example>

> **結論：** `code` 的用意不在於讓人直接看懂，而在於成為一個**絕對不會改變的錨點**。當使用者在 Sheets 中看到 `code = '01'` 時，是透過旁邊的「項目」、「素材名稱」、「人員」等欄位來理解其完整樣貌。n8n 在後台處理點擊事件時，也是認明 `code` 這個身分證字號，才知道要把成效歸於何處。

---

## 3. n8n 是否需要「廣告帳戶ID」？

<rule id="n8n-no-ad-account-id">
在理想的歸因流程中，n8n 的核心任務是處理歸因，確實**不需要**知道「廣告帳戶ID」。它只需知道「點擊事件的 `code`」以及「`code` 對應的 Pixel 和 CAPI Token」，即可完成將轉換事件回傳給 Meta 的關鍵工作。「廣告帳戶ID」是一個描述性資訊，主要用於在前台讓營運人員方便管理與對帳。
</rule>

目前流程會從 `消耗分頁` 讀取「廣告帳戶ID」並寫入 `成效分頁`，是基於舊版本 `manus_memory` 的歷史決策，旨在自動帶入固定資訊以節省手動操作。然而，這也使 n8n 的職責變得不夠純粹。

### 決策點

我們面臨兩個選擇，這取決於您的操作偏好：

1. **維持現狀**：n8n 繼續在首次建立 `code` 列時，自動從 `消耗分頁` 填入 `廣告帳戶ID`。此功能僅為方便起見，不參與核心歸因運算。
2. **移除此邏輯**：我們修改 n8n 工作流程，讓 `廣告帳戶ID` 成為一個**純手動欄位**。n8n 將不再讀寫此欄位，由您自行決定如何填寫。

我們建議選擇**選項 2 (移除此邏輯)**，因為這更符合「n8n 專注後台，Sheets 處理前台」的清晰劃分，讓系統架構更為簡潔。最終決定權在您手上。

## 總結與下一步

希望以上的深度解析能夠完整解答您的疑惑。總結來說：

- **職責劃分**：我們已對「n8n = 後台」、「Sheets = 前台」達成共識。
- **Code 用意**：`code` 是串聯前後台的唯一 ID，需搭配 Sheets 中的其他描述欄位才能讓人理解。
- **廣告帳戶ID**：n8n 核心歸因不需要它。我們提議將其從 n8n 流程中移除，改為純手動欄位。

我們等待您對於「將『廣告帳戶ID』改為純手動欄位」此提案的確認。一旦確認，我們將著手修改 n8n 工作流程以完成系統修復。
