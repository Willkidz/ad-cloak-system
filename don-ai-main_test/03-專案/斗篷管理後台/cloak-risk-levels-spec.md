> **TL;DR**: 本手冊建立了一套針對斗篷系統的四層風險管理框架：**Meta 層面**（最高風險，涉及規避系統拒絕）、**Cloudflare 層面**（基礎設施風險，涉及濫用投訴）、**公共聲譽層面**（外部黑名單）及**域名註冊商層面**。核心策略是「預防性棄用」與「資產隔離」，確保單一域名或帳號被封時不影響整體業務，並提供 15 分鐘內完成系統重建的應急流程。

# 斗篷系統：多層面風險等級與應對手冊

## 1. 核心理念

本手冊旨在提供一套清晰、可執行的風險管理框架。斗篷系統的成敗不僅在於技術實現，更在於對風險的**預判、隔離與應對**。我們將風險從高到低分為四個層面，並為每個層面的具體狀況定義了明確的處理流程。

<rule id="risk-levels">

**風險層面劃分（由高至低）：**
1.  **Meta (Facebook) 層面**：直接影響廣告投放，是最高風險區。
2.  **Cloudflare 層面**：影響基礎設施，處理不當會導致全盤癱瘓。
3.  **公共聲譽層面**：影響域名的外部信譽，可能間接影響 Meta 的判斷。
4.  **域名註冊商層面**：風險最低，通常只在涉及法律問題時出現。

</rule>

---

## 2. 風險應對矩陣

### 2.1. 第一層：Meta (Facebook) 風險

此層級的風險最為頻繁，要求最快的應對速度。

| 觸發事件 | 風險等級 | 根本原因分析 | 立即應對措施 |
| :--- | :--- | :--- | :--- |
| **廣告因「規避系統」被拒** | **高** | **域名被污染**。Meta 的爬蟲或 AI 系統已將您的域名與違規行為關聯。 | <step id="meta-risk-response">1. **立即停止**所有使用該域名的廣告活動。<br>2. 使用 **Meta 分享偵錯工具**確認域名是否被標記。<br>3. **永久棄用**該域名，將其歸檔。<br>4. 從備用池中啟用一個**全新、乾淨**的域名，更換 Safe Page 模板，微調廣告素材後重新提交。</step> |
| **廣告帳戶被禁用** | **極高** | 可能是域名問題的累積，也可能是付款方式、BM、粉絲頁等多重因素關聯導致。 | <step id="meta-acct-response">1. 這是 Meta 帳戶層面的問題，與斗篷技術本身關係不大。<br>2. 立即隔離與該帳戶關聯的所有資產：域名、Pixel、粉絲頁。<br>3. **不要**嘗試在新的廣告帳戶上使用任何舊的關聯資產。</step> |
| **分享偵錯工具顯示警告** | **中** | 域名可能被初步標記，或 Safe Page 內容觸發了某些敏感詞。 | <step id="meta-warn-response">1. **暫緩**使用該域名進行新的廣告投放。<br>2. 檢查 Safe Page 內容，移除任何可能有誤導性或誇大嫌疑的詞語。<br>3. 等待 24-48 小時後再次用偵錯工具檢查。如果警告仍在，建議**預防性棄用**。</step> |

---

### 2.2. 第二層：Cloudflare 風險

此層風險發生機率低，但一旦發生，將影響整個基礎設施。

| 觸發事件 | 風險等級 | 根本原因分析 | 立即應對措施 |
| :--- | :--- | :--- | :--- |
| **收到 Cloudflare 濫用投訴郵件** | **高** | 您的 Safe Page 或 Money Page 被安全廠商（如 Google Safe Browsing）或競爭對手惡意舉報。 | <step id="cf-abuse-response">1. **立即**根據郵件指引，暫時將被投訴的域名解析到一個完全無害的空白頁面。<br>2. 回覆 Cloudflare 郵件，表明您已處理該問題。<br>3. **永久棄用**該域名。Cloudflare 帳號雖然安全，但該域名已在 Cloudflare 留下不良記錄。</step> |
| **Cloudflare 帳號被暫停/封鎖** | **嚴重** | 極少見。通常是您在該帳號下託管了明確的非法內容，或長期無視濫用投訴。 | <step id="cf-ban-response">1. 根據備份策略，啟用一個**全新的 Cloudflare 備用帳號**。<br>2. 使用 Git Repo 中的程式碼重新部署 Worker 和 Pages。<br>3. 從 R2 或 Google Drive 恢復 D1 資料庫備份。<br>4. 將**全新的域名**添加到新帳號，並指向新的 Worker。<br>5. 整個重建過程應在 **15 分鐘內**完成。</step> |

---

### 2.3. 第三層：公共聲譽風險

此層面是外部信號，Meta 可能會參考這些信號來輔助判斷。

| 觸發事件 | 風險等級 | 根本原因分析 | 立即應對措施 |
| :--- | :--- | :--- | :--- |
| **域名被 VirusTotal、Spamhaus 等列入黑名單** | **中** | 您的域名被安全研究員或自動化系統標記為可疑。 | <step id="rep-bl-response">1. 暫停使用該域名投放廣告。<br>2. 檢查是否有誤報可能，如果確認是誤報，可嘗試向相關組織申訴移除。<br>3. **建議直接棄用**。申訴過程漫長且成功率不高，更換新域名的時間成本更低。</step> |

---

### 2.4. 第四層：域名註冊商風險

此層風險極低，除非涉及法律層面的問題。

| 觸發事件 | 風險等級 | 根本原因分析 | 立即應對措施 |
| :--- | :--- | :--- | :--- |
| **收到註冊商關於濫用的警告** | **低** | 通常是版權投訴 (DMCA) 或商標侵權，極少因為斗篷本身。 | <step id="reg-abuse-response">1. 評估投訴的合法性。<br>2. 如果投訴涉及 Money Page 的內容，請更換內容。<br>3. 如果您不想處理，最簡單的方法是**棄用該域名**，避免與註冊商發生法律糾紛。</step> |

---

## 3. 結論：預防勝於治療

成功的斗篷操作，核心在於**風險隔離與預防**，而非事後補救。

<rule id="asset-isolation">**資產隔離**：為每個核心廣告活動準備獨立的域名、Safe Page 模板、Cloudflare 帳號。</rule>
<rule id="proactive-monitoring">**主動監控**：定期使用 Meta 分享偵錯工具檢查主力域名的健康狀況。</rule>
<rule id="backup-readiness">**備份到位**：確保 Worker 程式碼和 D1 資料有可靠的自動化備份機制。</rule>

遵循此手冊，您將能系統性地管理風險，確保在問題發生時，能以最小的代價、最快的速度恢復運作。
