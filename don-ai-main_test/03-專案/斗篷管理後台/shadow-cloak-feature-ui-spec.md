> **TL;DR**: 本文件定義了「隱者斗篷」系統的技術藍圖。系統核心基於 Cloudflare Workers，具備 9 項過濾規則（如 ASN 封鎖、GeoIP）、7 項反向代理功能（含 HTML 內容改寫）及 6 項分流輪替機制。規劃包含完整的域名池管理與 UI 後台，並將開發劃分為七個階段，旨在完全替代第三方「火鳥」系統，實現流量的自主掌控與風險隔離。

# 隱者斗篷 — 完整功能清單與 UI 規劃

**系統定位**：本文件旨在規劃一個獨立的廣告流量管理系統，該系統將與「上帝視角」歸因系統進行無縫銜接，提供全面的流量過濾、代理、分流及管理功能。

---

## 1. 核心引擎功能（Worker 層）

此部分定義了系統在邊緣節點（Cloudflare Worker）上運行的核心邏輯，負責處理所有傳入的流量。

### 1.1. 流量過濾 (Traffic Filtering)

<rule id="traffic-filtering">
過濾規則旨在識別並攔截機器人或不符合條件的流量，確保只有真實用戶能訪問最終頁面。
</rule>

| 編號 | 功能 | 說明 |
| :--- | :--- | :--- |
| **A1** | **ASN 封鎖** | 自動封鎖來自超過 30 個已知數據中心（如 Meta, Google, AWS）的 ASN 流量。 |
| **A2** | **User-Agent 檢測** | 比對超過 50 種已知的爬蟲 User-Agent 特徵進行攔截。 |
| **A3** | **地理位置過濾** | 僅允許指定國家或地區（如 TW, HK, MO）的流量通過。 |
| **A4** | **空 UA 攔截** | 直接封鎖沒有 User-Agent 或字串過短（<10 字元）的請求。 |
| **A5** | **Referer 驗證** | 檢查請求的 Referer 是否來自預期的廣告平台點擊。 |
| **A6** | **IP 黑名單** | 提供手動介面，允許管理者加入特定的 IP 或 CIDR 段進行封鎖。 |
| **A7** | **IP 白名單** | 允許管理者 IP 繞過所有過濾，確保測試時永遠能看到真頁。 |
| **A8** | **頻率限制** | 當同一 IP 在短時間內發起大量請求時，自動進行臨時封鎖。 |
| **A9** | **規則自動更新** | 定時從 GitHub 等來源拉取最新的 ASN 與 IP 封鎖清單。 |

### 1.2. 反向代理 (Reverse Proxy)

<rule id="reverse-proxying">
反向代理是系統的核心，根據過濾結果將用戶導向不同目標，並在此過程中保護源站資訊。
</rule>

| 編號 | 功能 | 說明 |
| :--- | :--- | :--- |
| **B1** | **安全頁面代理** | 機器人流量被代理至安全的靜態頁面（白頁）。 |
| **B2** | **真實頁面代理** | 通過驗證的真實用戶被代理至實際的推廣落地頁（真頁）。 |
| **B3** | **內容改寫** | 動態改寫 HTML 中的域名引用，避免落地頁源站域名洩漏。 |
| **B4** | **靜態資源代理** | 頁面中的 CSS/JS/圖片等資源均通過 Worker 代理加載。 |
| **B5** | **備用白頁** | 當設定的安全頁面無法訪問時，自動返回內建的 HTML 備用頁。 |
| **B6** | **自訂落地頁** | 支援直接在 Worker 中內建簡單落地頁，無需依賴外部託管。 |
| **B7** | **多落地頁支援** | 允許根據不同路徑將流量代理到不同產品線的落地頁。 |

### 1.3. 輪替與分流 (Rotation & Splitting)

| 編號 | 功能 | 說明 |
| :--- | :--- | :--- |
| **C1** | **基本輪替** | 按設定的平均比例將流量分流到不同的後端標籤（Tag）。 |
| **C2** | **權重分流** | 支援自訂分流權重（例如 40%:30%:20%:10%）。 |
| **C3** | **分流暫停** | 允許單獨暫停某個標籤，流量將自動分配給其餘啟用標籤。 |
| **C4** | **fbclid 傳遞** | 在分流跳轉過程中，自動攜帶 Facebook 的 `fbclid` 參數。 |
| **C5** | **分流統計** | 即時統計每個標籤獲得的分流次數和實際比例。 |
| **C6** | **A/B 測試** | 支援同一產品線使用不同落地頁版本進行效果評估。 |

### 1.4. JS 管理 (JS Management)

| 編號 | 功能 | 說明 |
| :--- | :--- | :--- |
| **D1** | **像素自動注入** | 在代理頁面時，自動在 `</body>` 前注入 BC 像素追蹤碼。 |
| **D2** | **gotolink 改寫** | 自動將頁面中按鈕的跳轉連結改寫為通過 Worker 的分流端點。 |
| **D3** | **自訂 JS 注入** | 支援注入任意自訂程式碼（如離開意圖彈窗、返回鍵攔截）。 |
| **D4** | **版本管理** | 允許不同的產品線使用不同版本的 JS 腳本。 |

## 2. 域名與白頁管理

<rule id="management-modules">

### 2.1. 域名管理 (Domain Management)
- **域名池管理**：集中管理所有域名並標記角色（前端、安全頁、備用）。
- **狀態監控**：定時檢查域名是否被 Meta/Google 封鎖。
- **一鍵切換**：主域名被封時，一鍵切換廣告流量至備用域名。
- **自動配置**：新域名加入時自動完成 SSL、DNS 與 Worker 路由配置。

### 2.2. 安全頁面管理 (Safe Page Management)
- **模板庫**：預建多套不同主題（健康、理財、教育）的白頁模板。
- **快速切換**：不同廣告素材對應不同白頁，支援 A/B 測試。
- **合規檢查**：自動檢查白頁是否包含隱私政策、服務條款等必要內容。

</rule>

## 3. UI 管理介面規劃

### 3.1. 頁面結構

| 頁面 | 功能 | 優先級 |
| :--- | :--- | :--- |
| **儀表板** | 即時流量、機器人比例、分流統計、告警通知 | 中 |
| **域名管理** | 域名池、狀態監控、角色分配、一鍵切換 | 中 |
| **產品線管理** | 產品線 + Tag + 分流規則 + 像素綁定 | 中 |
| **連結工具** | 連結生成、批量生成、測試工具、短連結 | **高** |
| **過濾規則** | ASN/UA/Geo/IP 黑白名單管理 | 低 |

## 4. 系統優勢對比

| 項目 | 火鳥（第三方服務） | 隱者斗篷（自研系統） |
| :--- | :--- | :--- |
| **JS 注入** | 手動粘貼，操作繁瑣 | **Worker 自動注入，全域生效** |
| **分流邏輯** | 固定且單一 | **可自訂權重、動態暫停、A/B 測試** |
| **域名控制** | 使用共享域名，風險高 | **使用自有域名，完全掌控與隔離** |
| **訪問速度** | 依賴第三方伺服器 | **Cloudflare 邊緣節點，全球加速** |

## 5. 開發順序建議

<step id="development-phases">

1.  **第一階段 — 核心功能**：實現基礎流量過濾與代理能力（A1-A4, B1-B5）。
2.  **第二階段 — 操作便利性**：提供連結生成與分流工具（C2-C3, H1-H4）。
3.  **第三階段 — 監控與告警**：建立 D1 日誌體系與 Telegram 告警（G1-G6）。
4.  **第四階段 — JS 自動化**：實現像素注入與按鈕連結改寫（D1-D4）。
5.  **第五階段 — 規模化管理**：引入完整的域名自動化管理（E1-E6）。
6.  **第六階段 — UI 介面**：開發可視化管理後台。

</step>
