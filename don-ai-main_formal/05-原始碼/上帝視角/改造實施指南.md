# 隱者系統改造實施指南：全面轉換為直接連結與時間窗口歸因

本指南詳細說明如何將現有系統全面從「LIFF 授權畫面跳轉」改為「直接連結（302 跳轉）+ N8N 45 秒時間窗口歸因」的架構。此方案能達成零許可畫面，並確保歸因流程順暢運作，同時不影響現有火鳥系統的運作。

## 一、改造背景與目標

本次改造的核心目標在於移除所有標籤的 LIFF 授權畫面，改以直接連結（302 跳轉）方式將用戶引導至 LINE 官方帳號，並透過時間窗口匹配機制來完成事件歸因。

**核心要求包含：**
- 確保「事件編號」、「訪客編號」、「臉書點擊編號」、「用戶編號」四個關鍵欄位能正常抓取與寫入。
- 所有標籤統一走直接 302 跳轉到 LINE 加好友連結。
- N8N 採用 45 秒時間窗口匹配作為唯一歸因路徑。
- 確保隱者系統與火鳥系統兩套邏輯並存且互不干擾。

## 二、檔案修改說明

### 1. `line-redirect.js`（位於 `05-原始碼/上帝視角/`）

**修改內容：**
- 清空了 LIFF 標籤集合，廢棄了原有的 LIFF 頁面渲染跳轉邏輯。
- 所有進入此程式的請求，在寫入「點擊紀錄」資料表後，統一執行 302 重導向，直接跳轉至 LINE 加好友連結。

**修改原因：**
- 為了達成「零許可畫面」的需求，直接跳轉能減少用戶流失。保留了原有的 LIFF 對應表設定，以備未來若需針對特定標籤恢復 LIFF 流程時可快速調整。

### 2. `shadow-cloak.js`（位於 `05-原始碼/斗篷管理後台/`）

**修改內容：**
- 在「取得活動配置」函數的資料庫查詢中，新增了「目標帳號」欄位的讀取。
- 在「點擊紀錄」資料表的寫入語句中，新增了「目標帳號」欄位的寫入，其值取自活動配置中的目標帳號。

**修改原因：**
- 「目標帳號」（即 LINE 官方帳號的用戶編號）是 N8N 時間窗口歸因的關鍵匹配條件。將其寫入點擊紀錄表，能確保 N8N 在收到 LINE 加好友事件時，能準確對應到正確的官方帳號點擊紀錄。
- 寫入時標記了來源為「隱者斗篷」，以確保與火鳥系統的資料隔離。

### 3. `money-page.js`（位於 `05-原始碼/上帝視角/`）

**修改內容：**
- 更改了行動呼籲按鈕的網址組裝邏輯。原先組裝為 LIFF 連結，現在改為指向跳轉中繼程式，格式為 `https://{標籤}.freshpathlab.com/{廣告編號}?vid={訪客編號}`。
- 更新了前端的按鈕點擊事件監聽器，當點擊行動呼籲按鈕時，觸發的統計像素事件由原先的「購買」改為「潛在客戶」，以符合新的追蹤規範。

**修改原因：**
- 配合廢棄 LIFF 的策略，將流量直接導向跳轉中繼程式，由該程式負責記錄點擊並執行 302 跳轉。這確保了所有跳轉都經過我們控制的節點，能準確記錄訪客編號與臉書點擊編號等資訊。

### 4. N8N 工作流程（位於 `05-原始碼/上帝視角/n8n_time_window_workflow.json`）

**修改內容：**
- 移除了原有的「精確查詢點擊」與「精確匹配」節點（依賴 LIFF 傳回的用戶編號）。
- 替換為「查詢近期點擊」與「時間窗口匹配」節點。
- 查詢條件改為：目標帳號相符、尚未匹配、且點擊時間在加好友事件前 45 秒內。
- 若在 45 秒內有多筆點擊，則取時間最接近的一筆進行歸因。

**修改原因：**
- 由於改用直接跳轉，我們無法在跳轉前取得用戶的 LINE 用戶編號。因此，必須依賴 LINE 回傳的加好友事件時間，往前回推 45 秒，在資料庫中尋找符合該官方帳號（目標帳號）的未匹配點擊紀錄，以此完成歸因。

## 三、部署與上線步驟

1. **部署 Cloudflare Workers**
   - 部署修改後的 `line-redirect.js`（跳轉中繼程式）。
   - 部署修改後的 `shadow-cloak.js`（斗篷程式）。
   - 部署修改後的 `money-page.js`（推廣頁程式）。

2. **更新 N8N 工作流程**
   - 登入 N8N 管理介面。
   - 匯入本指南附帶的工作流程檔案。
   - 確認回呼網址與資料庫的認證資訊設定正確。
   - 啟用該工作流程，並停用舊版的 LIFF 歸因工作流程。

3. **資料庫欄位確認**
   - 確保資料庫的「活動配置」資料表中，所有活躍的活動都已正確設定「目標帳號」欄位（對應的 LINE 官方帳號用戶編號）。
   - 確保「點擊紀錄」資料表已包含「目標帳號」欄位。

4. **測試驗證**
   - 產生一個測試用的推廣連結，並點擊進入推廣頁。
   - 點擊行動呼籲按鈕，確認是否順利 302 跳轉至 LINE 加好友畫面（無 LIFF 許可畫面）。
   - 加入好友後，檢查資料庫的「點擊紀錄」表，確認該筆點擊的「已匹配」欄位是否成功更新為 1，且「匹配用戶編號」已填入。
   - 檢查臉書事件管理工具，確認廣告像素與統計像素是否成功接收到「完成註冊」事件。

## 四、注意事項

- **火鳥系統相容性**：本次修改僅針對隱者系統（透過斗篷程式進入的流量）。火鳥系統的落地頁與跳轉邏輯維持不變，兩者透過「來源」欄位在資料庫中隔離，互不影響。
- **時間窗口限制**：45 秒的時間窗口是基於一般用戶點擊到加好友的操作時間所設定。若發現歸因率下降，可適度調整 N8N 查詢與程式中的時間窗口參數。

## 五、欄位對照表

| 中文名稱 | 程式碼欄位名 | 說明 |
|:---|:---|:---|
| 事件編號 | event_id | 每次點擊產生的唯一事件識別碼 |
| 訪客編號 | visitor_id / vid | 每位訪客的唯一識別碼 |
| 臉書點擊編號 | fbclid | 臉書廣告點擊帶來的追蹤參數 |
| 用戶編號 | user_id / line_user_id | LINE 用戶的唯一識別碼 |
| 目標帳號 | destination | LINE 官方帳號的用戶編號 |
| 已匹配 | matched | 是否已完成歸因匹配（0=否，1=是） |
| 匹配用戶編號 | matched_user_id | 匹配成功後寫入的 LINE 用戶編號 |
| 廣告編號 | ad_code | 廣告代號（如 MX09） |
| 標籤 | tag | 產品線標籤（如 mx） |
| 來源 | source | 流量來源（隱者斗篷 或 火鳥） |
