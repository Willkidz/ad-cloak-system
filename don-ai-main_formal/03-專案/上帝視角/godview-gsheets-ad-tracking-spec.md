# Google Sheets 廣告成效追蹤系統規格書 (v7)

---

## 總覽

本文件旨在詳細說明「上帝視角」專案中，Google Sheets 作為廣告成效追蹤前台的核心規格與運作邏輯。目標是提供一份清晰、完整的指南，讓 Excel/Google Sheets 專家能夠理解並基於此進行後續的優化與開發。

<rule id="core-concept">

本系統的核心設計理念是「**n8n = 後台（配置中心），Sheets = 前台（營運儀表板）**」。n8n 負責處理複雜的數據歸因與自動化寫入，而 Sheets 則專注於提供一個清晰、易於操作的人機互動介面，供廣告人員進行數據監控、手動填寫與決策分析。

</rule>

---

## 工作表結構

整個 Google Sheets 檔案包含以下幾個核心工作表：

| 工作表名稱 | 主要功能 |
| :--- | :--- |
| **成效** | 核心儀表板，展示所有廣告活動的成效數據與系統偵測率。 |
| **3月消耗** | 原始數據表，由廣告人員手動貼上從廣告後台匯出的每日消耗數據。 [待確認]：建議改為通用名稱如「原始消耗數據」。 |
| **_添加日誌** | n8n 自動寫入的原始日誌，記錄每一筆成功歸因的 LINE 好友添加事件。 |
| **_消耗日誌** | n8n 自動寫入的日誌，記錄每日從「3月消耗」表中讀取並處理的廣告消耗。 |
| **_每日快照** | n8n 自動寫入的日誌，記錄每日每條廣告的消耗與添加數，用於歷史數據分析。 |

## 「成效」工作表詳解

「成效」工作表是整個系統的門面，分為三個主要區塊：**A. 控制面板**、**B. 偵測率驗證區**、**C. 廣告成效數據區**。

### 控制面板 (A1:H2)

此區塊用於控制報表的數據範圍與查看系統狀態。

| 儲存格 | 標題 | 內容 (範例) | 說明 |
| :--- | :--- | :--- | :--- |
| **B2** | 開始日期 | `2026-03-10` | 手動填寫，n8n 會讀取此日期作為數據計算的起始點。 |
| **C2** | 結束日期 | `2026-03-15` | 手動填寫，n8n 會讀取此日期作為數據計算的結束點。 |
| **D2** | 區間類型 | `自訂` | 手動填寫或下拉選單（今天/昨天/近7天/本月/自訂）。n8n 會根據此設定自動調整 B2 和 C2 的日期。 |
| **F2** | 最後更新時間 | `2026-03-15 19:55:01` | **n8n 自動寫入**，顯示工作流程最後一次成功運行的時間。 [已過期：日期為舊資料] |
| **H2** | 最後同步事件ID | `12345` | **n8n 自動寫入**，記錄 `godview_events` 中已處理的最新事件 ID，避免重複計算。 |

### 偵測率驗證區 (A3:E7)

此區塊用於驗證 n8n 歸因系統的準確度。

| 欄位 | A | B | C | D | E |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Row 3** | **人員** | **項目** | **真實添加** | **系統抓取** | **偵測率** |
| **Row 4** | C | X,S,B | （手動填寫） | （n8n 自動） | `=IF(C4="","",D4/C4)` |
| **Row 5** | J | X,S,B,D | （手動填寫） | （n8n 自動） | `=IF(C5="","",D5/C5)` |
| **Row 6** | L | X,S,B | （手動填寫） | （n8n 自動） | `=IF(C6="","",D6/C6)` |
| **Row 7** | M | X,S,B | （手動填寫） | （n8n 自動） | `=IF(C7="","",D7/C7)` |

- **C 欄 (真實添加)**：由廣告人員手動填寫，來源是各推廣人員從 LINE 官方後台回報的、在指定區間內的真實好友增加數。
- **D 欄 (系統抓取)**：**n8n 自動寫入**。n8n 會根據 `line_config` 的設定，加總該人員名下所有 LINE 帳號在指定區間內被成功歸因的添加數。
- **E 欄 (偵測率)**：**Sheets 公式**，計算 D/C 的比值，用於評估歸因準確度。

### 廣告成效數據區 (A11:N)

此區塊是報表的主體，以廣告 `code` 為單位，展示詳細的成效數據。Row 11 為標題列，Row 12 開始為數據。

| 欄 | 標題 | 數據來源 | 說明 |
| :--- | :--- | :--- | :--- |
| **A** | **code** | n8n 自動 | 廣告的唯一識別碼，格式為 `[導向][項目][序號]`，如 `AS01`。 |
| **B** | **廣告帳戶ID** | 手動填寫 | 由廣告人員手動填寫，方便對應廣告後台。n8n 會保留此欄位原有的值。 |
| **C** | **素材說明** | 手動填寫 | 由廣告人員手動填寫，備註該 `code` 對應的廣告素材內容。n8n 會保留此欄位原有的值。 |
| **D** | **狀態** | n8n 自動 | 根據「3月消耗」表中的狀態自動更新為「進行中」或「已暫停」。 |
| **E** | **累計消耗** | n8n 自動 | 從「3月消耗」表中累計該 `code` 的總花費。 |
| **F** | **累計添加** | n8n 自動 | 從 `godview_events` 中累計該 `code` 的歷史總添加數。 |
| **G** | **累計CPA** | n8n 自動 | `累計消耗 / 累計添加`。 |
| **H** | **區間消耗** | n8n 自動 | 從「3月消耗」表中累計該 `code` 在指定區間內的花費。 |
| **I** | **區間成果** | 手動填寫 | 由廣告人員手動填寫，例如該 `code` 在區間內帶來的訂單數或營收。n8n 會保留此欄位原有的值。 |
| **J** | **區間添加** | n8n 自動 | 從 `godview_events` 中累計該 `code` 在指定區間內的添加數。 |
| **K** | **流失** | Sheets 公式 | `=IF(AND(I12="",J12=""),"",I12-J12)`。比較手動填寫的「成果」與系統抓取的「添加」。 |
| **L** | **添加占比** | Sheets 公式 | `=IFERROR(IF(I12>0,J12/I12,""),"")`。計算系統添加數佔手動成果數的比例。 |
| **M** | **單次添加** | n8n 自動 | `區間消耗 / 區間添加`，即區間 CPA。 |
| **N** | **單次成果** | Sheets 公式 | `=IFERROR(IF(I12>0,H12/I12,""),"")`。基於手動成果計算的單次成本。 |

## n8n 自動化寫入邏輯

以下是 n8n 工作流程 `上帝視角_Sheets Report - Daily Stats` 與此 Sheets 互動的核心邏輯。

<step id="read-settings">

**1. 讀取設定**：工作流程啟動後，首先會讀取「成效」工作表的 A2:H2 儲存格，以取得日期區間、區間類型和最後同步的事件 ID。

</step>

<step id="read-manual-data">

**2. 讀取手動數據**：
   - 讀取「3月消耗」工作表的所有內容，以計算廣告消耗。
   - 讀取「成效」工作表的 A12:N 範圍，以取得現有的手動填寫欄位（如廣告帳戶ID、素材說明、區間成果）。

</step>

<step id="read-n8n-data">

**3. 讀取 n8n 數據**：
   - 從 `godview_events` DataTable 中讀取 `lastSyncedId` 之後的所有 `line_friend_added` 事件。
   - 從 `line_config` DataTable 中讀取人員與 LINE 帳號的對應關係。

</step>

<step id="calculate-and-aggregate">

**4. 計算與彙總**：在 n8n 內部，程式碼會根據讀取到的數據，計算出每個 `code` 的區間消耗、總消耗、區間添加、總添加等指標。同時，會根據 `line_config` 計算出每位人員（C/J/L/M）的系統抓取總數。

</step>

<step id="write-data">

**5. 寫入數據**：計算完成後，n8n 會透過 Google Sheets API，將數據一次性地寫入到「成效」工作表的指定位置：
   - **D4:D7**：寫入 C/J/L/M 四位人員的「系統抓取」數。
   - **A12:N**：更新整個廣告成效數據區。對於手動欄位，會保留原值；對於自動欄位，會寫入最新的計算結果；對於公式欄位，會直接寫入帶有正確行號的 Sheets 公式字符串。
   - **F2 & H2**：更新「最後更新時間」和「最後同步事件ID」。

</step>

<step id="write-logs">

**6. 寫入日誌**：
   - 將本次歸因到的新添加事件寫入「_添加日誌」。
   - 將本次計算的消耗數據寫入「_消耗日誌」。
   - 將當日的 `code`、消耗、添加數寫入「_每日快照」。

</step>

## 附錄：其他工作表規格

### 「3月消耗」工作表

- **用途**：存放從廣告後台（如 Meta）每日匯出的原始消耗數據。
- **格式**：結構必須固定，n8n 的程式碼依賴此結構解析。
- **關鍵欄位** (n8n 會讀取)：
    - `C欄 (Column C)`: **廣告帳戶ID**
    - `D欄 (Column D)`: **素材**
    - `H欄 (Column H)`: **狀態**
    - `I欄 (Column I)`: **code**
    - `J欄 (Column J)`: **人員**
    - `K欄 (Column K)`: **項目**
    - `M欄 (Column M)` 之後: **每日消耗** (日期格式為 `MM/DD`)

### 「_每日快照」工作表

- **用途**：作為數據倉庫，每日記錄，方便進行長期的趨勢分析。
- **格式**：
    - `A欄`: 日期 (YYYY-MM-DD)
    - `B欄`: code
    - `C欄`: 當日消耗
    - `D欄`: 當日添加
